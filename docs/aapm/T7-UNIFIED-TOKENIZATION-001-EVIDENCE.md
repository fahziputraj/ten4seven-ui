## 3. Token taxonomy changes

The canonical source remains:

- `packages/contracts/src` for typed contract decisions and semantic
  ownership;
- `packages/tokens/src/theme.ts` for resolved Web and Native token values;
- generated CSS, DTCG, and agent projections for distribution.

`STYLE_TOKENIZATION_CONTRACT` was added to the existing foundation contract as
governance vocabulary, not as a second token registry. It defines these
layers:

1. primitive;
2. semantic;
3. component;
4. product-profile;
5. composition-local;
6. renderer-projection.

It defines bounded exception classes for token authority, mechanical values,
intrinsic geometry, runtime-derived values, motion choreography,
composition-local values, test fixtures, and external API requirements.

The source token model was extended with:

- named reference rhythm values (`micro`, `fine`, `compact`, `tight`, `quiet`,
  `inline`, `snug`, `relaxed`, and `hero`) while preserving the existing
  numeric reference scale;
- shared mark geometry for choice marks, radio marks, dots, and strokes;
- interaction feedback opacity roles for interactive, hover, active, disabled,
  choice, option, checkbox, chart, and detail-entry states;
- native icon and mark projections derived from the same token source as Web
  geometry.

All generated projections were regenerated after these source changes.

## 4. Canonical Web migration

The repeated foundation values in `packages/ui/src/styles.css` and the active
playground stylesheet were mechanically replaced with canonical variables.
The migration covers common:

- gaps and section rhythm;
- padding and margins;
- control-height roles;
- reference-space aliases;
- repeated interaction opacity values;
- chart/detail alpha roles.

The change keeps component anatomy and route composition intact. It does not
introduce local Button, Card, Input, layout, motion, or theme primitives.
Existing layout formulas, intrinsic geometry, browser hairlines, transforms,
and token-backed composition remain bounded exceptions where a semantic
consumer token would not be correct.

Generated Web outputs include:

- `packages/tokens/src/theme.css`;
- `packages/tokens/src/theme-recipes.css`;
- `generated/foundation.json`;
- `generated/native-mobile.json`;
- `generated/tokens.dtcg.json`;
- corresponding `packages/agent/generated/*` and
  `packages/tokens/generated/tokens.dtcg.json` projections.

The two ColorPicker fixture preset lists no longer own hex palettes. Both
`component-preview-fixtures.tsx` and `component-proofs.tsx` now use the small
`fixture-theme.ts` renderer helper, which resolves the active canonical theme
with `buildThemeVariables` and converts the resolved HSL channels to the hex
format required by the native HTML color input. This keeps the fixture
behavior while removing repeated demo-local color ownership.

Theme Studio and the token inspector continue to serialize resolved HSL values
for visual inspection. Those values are explicitly classified as
`RUNTIME_DERIVED`; they originate from the canonical resolver or computed CSS
variables and are not a second palette.

The route stylesheet keeps only scoped composition aliases such as publishing
accent, Theme Studio preview color, and profile-preview color. These aliases
reference canonical semantic/profile variables and are recorded as bounded
runtime projections in the exception registry.

## 6. Native/Expo migration

Native remains CSS-independent. The migration added typed projections for:

- five icon size roles: compact, control, navigation, status, and feature;
- four mark roles: choice, radio, dot, and stroke.

`buildNativeThemeSnapshot` resolves these values from the shared theme. The
Native renderer now uses the projected icon size when no explicit size is
provided, uses projected mark geometry for choice/radio controls, and derives
the master-detail minimum from the shared compact measure. Native Lab spacing
and minimum-width examples also consume the typed theme snapshot.

No Web CSS is parsed by Native or Expo code, and no parallel Native theme
authority was added.

## 7. Layout tokenization

The migration uses the existing layout measure contract for meaningful
container measures and adds only reference rhythm names needed to eliminate
repeated common spacing literals. It does not promote every intrinsic value to
a global axis.

The following remain intentionally local where their meaning is mechanical or
intrinsic:

- percentage and viewport constraints;
- content-sized and clamp-based bounds;
- hairlines and small indicators;
- chart, icon, media, and mark anatomy;
- pointer/transform offsets;
- component-internal geometry with no cross-component semantic role.

The governance registry requires these values to carry an owner and reason.
No duplicate `:root` block containing `--t7-*` was found outside the canonical
token authority.

## 8. Typography, elevation, and motion normalization

Typography, elevation, and motion remain on existing Ten4Seven contracts:

- repeated typography roles continue to reference the canonical type scale;
- repeated shadows and inset depth use shared semantic elevation/color values;
- interaction alpha values are emitted by `INTERACTION_FEEDBACK` and projected
  as `--t7-opacity-*` variables;
- motion continues to use `t7Motion` / existing duration and easing roles;
- no new animation framework, local timing runtime, keyframe system, or raw
  transition duration was introduced.

The motion-choreography exception is limited to mathematical opacity endpoints
inside the canonical motion implementation. It does not permit a consumer
critical surface to start blank.
